# 介面契約 — 組織圖工作台（/workbench）

> 協調者產出的總契約。對應已批准計畫（plan：整合性主介面）。各角色照本契約開發、不得自改契約。
> 願景：以組織圖拖拉為中心的整合主介面，把各功能即時嵌入、需要細節才引導出去。
> 狀態：階段 1 開工。最後更新：2026-06-07。

## 0. 總綱

**架構決策**：抽 `useOrgFlowEditing()`（把 OrgChartPage 的編輯 session 編排抽出）→ 新建 `/workbench` 用同一 hook 換版面 → **保留 `/org-chart` 當對照與回滾**。OrgFlowChart 畫布已 props-driven，不複製。後端零改動。

**四階段交付**（各自走 6+4 管線、可獨立驗收、可回滾）：
1. **地基**（本契約 §1）：抽 `useOrgFlowEditing` + 抽 `FindingGroup` 共用 + `/workbench` 骨架（中央畫布 + 既有編輯路徑）+ 路由/導覽。
2. **即時整合面板**：頂欄 delta + 右側 findings/職能/readiness（CM 防過載分層）+ 選中節點該人提醒 + 引導連結。
3. **drag-to-reassign**：拖人到主管節點下＝改匯報線（getIntersectingNodes + validators 防護 + 手勢語意 + 鍵盤替代）。
4. **延伸角度**：流程衝擊摘要 + scenario 局部比較入口。

**重用清單**：OrgFlowChart、各 chrome、useDraggableFlowNodes、useEditSession、EditModeToolbar、EditImpactBar、FunctionCoveragePanel、OrgDetailPanel、SnapshotPanel、OrgHealthPage 的 FindingGroup、所有分析純函式（orgHealth/functionCoverage/processImpact）、validators。

## 1. 階段 1 — 地基（本輪範圍）

### 1.1 抽 `useOrgFlowEditing()` hook
**新檔**：`src/hooks/useOrgFlowEditing.ts`（或 src/components/orgFlow/，挑與既有 hook 一致的位置）。

把 `OrgChartPage.tsx` 目前的「編輯 session 編排」整坨抽出（目前散在 OrgChartPage 約 L60-169）：
- `useEditSession()` 的使用
- `staleDataWarning`（偵測編輯中底層發布版本被改）+ `prevPublishedRef`
- `orgData` 解析（編輯中用 draftData、否則用 published `data`）
- `baseHealth` / `draftHealth` / `impactDelta` 三個 memo（沿用既有依賴細化：base 依 `session.baseData`、draft 依 `session.draftData`）
- `diffResult`（previewingSnapshotId 的 diff）
- handlers：`handleEnterEditMode` / `handleExitEditMode` / `handleSaveCheckpoint` / `handlePublish(opts)` / `handleDraftChange`
- 接 `useOrg()`（data / publishVersion）

**回傳介面**（供頁面組裝，命名可微調但語意如下）：
```ts
interface UseOrgFlowEditing {
  isEditMode: boolean;
  session: EditSession | null;
  orgData: OrgData;              // 當前該顯示的資料（draft 或 published）
  impactDelta: OrgHealthDelta | null;
  diffResult: OrgDiffResult | null;
  staleDataWarning: boolean;
  enterEditMode: () => void;
  exitEditMode: () => void;
  saveCheckpoint: (desc: string) => void;
  publish: (opts: { label?: string; note?: string; effectiveDate?: string }) => void;
  onDraftChange: (next: OrgData) => void;
  previewSnapshot: (id: string | null) => void;
  rollbackToSnapshot: (id: string) => void;
  dismissStaleWarning?: () => void;  // 若原本有
}
```

**關鍵約束**：`OrgChartPage.tsx` 改用此 hook 後**行為完全等價**——既有 `OrgChartPage.test.tsx` 與其他相關測試**必須全綠且不需修改斷言**（這是重構等價的證明）。memo 依賴細化要保留（避免 stale，先前踩過的雷）。

### 1.2 抽 `FindingGroup` 共用元件
**新檔**：`src/components/orgHealth/FindingGroup.tsx`（或合適的共用位置）。

從 `OrgHealthPage.tsx`（目前內部 function，約 L222）抽出 `FindingGroup`：props 為一組 category 的 findings + 中文標籤 + 數量等（依現有實作）。沿用既有 details/summary 摺疊 + a11y（紅點 aria-label、focus-visible）。`OrgHealthPage.tsx` 改 import 此共用元件，**行為等價、既有測試全綠**。

### 1.3 新建 `WorkbenchPage` 骨架
**新檔**：`src/pages/WorkbenchPage.tsx`，路由 `/workbench`。

階段 1 範圍（骨架，面板留階段 2）：
- 用 `useOrgFlowEditing()` 取狀態與 handlers。
- 中央放 `OrgFlowChart`（reporting 視角、含編輯）——與 /org-chart 的 reporting 編輯能力等價：進編輯、拖層級、連線改主管、`OrgDetailPanel` 編輯、儲存檢查點、發布。
- 頂部放 `EditModeToolbar`（重用）。
- 階段 1 **先只做 reporting 視角**（membership 雙視角留階段 2）；右側即時面板、drag-to-reassign 留階段 2/3。
- 頁首簡短標題「組織圖工作台」+ 一句定位。
- staleDataWarning 沿用 OrgChartPage 的呈現方式。

> 目標：階段 1 結束時，/workbench 是一個「能完整編輯+發布的組織圖頁」，與 /org-chart reporting 等價，只是獨立頁——作為後續階段疊加面板的容器。

### 1.4 路由與導覽

## 2. 階段 2 — 即時整合面板（本輪範圍）

目標：讓 /workbench 從「編輯骨架」變成「整合主介面」——編輯/檢視時右側即時呈現各角度提醒、選中節點看該人提醒、提供引導出去的連結。**僅動 WorkbenchPage 與其新子元件 + 必要的共用版面抽取；OrgChartPage 行為維持等價。後端零改動。**

### 2.0 先還技術債：抽共用 reporting 編輯版面
階段 1 留下 WorkbenchPage 與 OrgChartPage 的 reporting 編輯版面重複（staleWarning Alert、EditModeToolbar+EditImpactBar+OrgFlowChart+SnapshotPanel 組裝、`pickDefaultGroupId`/`resolveGroupId`、魔術值）。抽成共用元件（如 `src/components/orgFlow/ReportingEditCanvas.tsx`，props：`editing`(useOrgFlowEditing 回傳)、groupId 狀態等），OrgChartPage 與 WorkbenchPage 都用。
- **約束**：OrgChartPage 行為等價，既有測試全綠不改斷言。
- 前端可判斷最小切法（全抽 or 只抽重複片段），以「等價 + 去重」為準。

### 2.1 右側即時面板（可摺疊）
WorkbenchPage 右側新增可摺疊側欄（landmark + aria-label），內容即時反映 `orgData`（編輯中＝draft）：
- **規劃就緒度徽章**：`buildReadiness(buildOrgHealth(orgData))` 的 total + level。
- **即時提醒（findings）**：用既有共用 `FindingGroup` 分群呈現 `buildOrgHealth(orgData).findings`。**CM 防過載**：預設只顯示 warning（最該看），提供「展開全部（含 info）」切換。
- **職能覆蓋**：重用 `FunctionCoveragePanel`（`buildFunctionCoverage(orgData)`）。
- **效能**：右側面板共用一個 `useMemo(() => buildOrgHealth(orgData), [orgData])`，findings 與 readiness 都從它來；FunctionCoverage 另一個 `useMemo([orgData])`。

### 2.2 選中節點 → 該人相關提醒
- WorkbenchPage 取得目前選中的 employeeId。**接點**：OrgFlowChart 內部目前管選中（OrgDetailPanel），需把 selectedEmployeeId lift 到 WorkbenchPage（或經 OrgFlowChart 既有回調）。前端評估最小改法，且**不可破壞 OrgChartPage 的選中行為**（若改 OrgFlowChart 介面，OrgChartPage 也要同步且等價）。
- 有選中時：右側面板頂部顯示「{姓名} 的相關提醒」＝ `findings.filter(f => f.employeeId === selectedId)`；無選中時顯示全域 findings。

### 2.3 引導連結區
WorkbenchPage 底部「需要細節？」區，用 Link 連到 `/people`、`/groups`、`/compare`、`/bpmn/impact`、`/csv-import`，各附一句說明。

### 2.4 範圍外（後續階段）
drag-to-reassign（階段 3）；membership 雙視角、流程衝擊摘要、scenario 局部入口（階段 4）。
