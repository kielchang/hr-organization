# 代辦清單（Backlog）

> 由 Claude 在 `integration` 分支逐項完成；每項完成即推送（pre-push 驗證把關）。

## 定位（最高指導原則）

本工具為 **HR 規劃／試算工具**（匯報線 × 專案職能），不是全公司營運系統。
BPMN 是組織變更影響的**輔助透鏡**，非簽核引擎。
偏全公司營運系統的項目（送簽、SSO、多租戶、後端正規化）已**降為非主線**。

---

## 收尾路線圖（M1 → M4）

依「整個專案完成 = HR 能完整走完一個組織規劃決策流程」推導，剩這四個里程碑。

### M1. 規劃情境比較 what-if 〔下一個開工〕
**解決**：HR 通常擬 2–3 個方案討論再選，現在沒法並排比。
- 並排多個發布版本（或草稿）
- 比 diff（重用 `computeOrgDiff`）+ 比規劃健檢指標（重用 `orgHealth`）
- 推薦或差異標示，協助選定方案

### M2. BPMN 影響分析重定位
**解決**：現有 BPMN 像「流程設計工具」，HR 看了會困惑。
- 把 `BpmnImpactPage` 從「流程設計輔助」收斂為「**HR 變更影響透鏡**」
- 文案／版面／導覽動線調整
- BPMN 設計／模擬頁不刪，降為次層入口

### M3. 整合 UX 收尾
**解決**：功能都有了但沒人告訴使用者該怎麼用這套工具。
- 首頁／引導頁串「載入 → 編輯 → 健檢 → 比較 → 影響 → 發布」
- 動線整理、空狀態提示

### M4. README + 使用者導引
**解決**：技術文件齊但缺使用者面陳述。
- 寫使用者面 README（這個工具是給誰、解決什麼、怎麼用）
- walkthrough（依典型 HR 規劃旅程）
- 收尾整理（archive 完成項目、清掉死連結）
