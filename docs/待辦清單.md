## 定位（最高指導原則）

本工具為 **HR 規劃／試算工具**（匯報線 × 專案職能），不是全公司營運系統。
BPMN 是組織變更影響的**輔助透鏡**，非簽核引擎。
偏全公司營運系統的項目（送簽、SSO、多租戶、後端正規化）已**降為非主線**。

## 收尾路線圖（M2 → M4）

依「整個專案完成 = HR 能完整走完一個組織規劃決策流程」推導；M1 已完成，剩下三個里程碑。

### M2. BPMN 影響分析重定位 〔下一個開工〕
**解決**：現有 BPMN 像「流程設計工具」，HR 看了會困惑。
- 把 `BpmnImpactPage` 從「流程設計輔助」收斂為「**HR 變更影響透鏡**」
- 文案／版面／導覽動線調整
- BPMN 設計／模擬頁不刪，降為次層入口

### M3. 整合 UX 收尾
**解決**：功能都有了但沒人告訴使用者該怎麼用這套工具。
- 首頁／引導頁串「載入 → 編輯 → 健檢 → 比較 → 影響 → 發布」
- 動線整理、空狀態提示

### M4. README + 使用者導引
**解決**：技術文件齊但缺使用者面陳述。
- 寫使用者面 README（這個工具是給誰、解決什麼、怎麼用）
- walkthrough（依典型 HR 規劃旅程）
- 收尾整理（archive 完成項目、清掉死連結）

## 已完成（按時間倒序，細節在系統設計文件與契約文件）

### HR 規劃主線
- ✅ **M1 規劃情境比較 what-if**（commit `01c29d0`，契約見 [契約-情境比較 what-if](契約-情境比較whatif.md)）
  - `scenarioCompare.ts` 純函式 `buildScenarioComparison(inputs)`：入口先 `backfillAssignmentLevels` 正規化、以陣列首個情境為基準呼叫 `computeOrgDiff(baseline → current)`、各情境跑 `buildOrgHealth`，產出 10 指標的 `metricMatrix`（`warningCount` / `functionsWithoutMembers` / `functionsWithoutLead` / `spofCount` 標 `down`，其餘 `neutral`）與 8 計數的 `diffSummary`
  - `/compare` 頁 + 導覽入口「情境比較」：最多 4 個情境槽，資料源為 `useOrg().dataVersions`（含內建種子、mock、發布版本、雲端版本）；無效版本選項 disabled 並標「✗（格式錯誤）」
  - 互動細節：首槽預設 active 版本；第一個有效槽自動為基準（`baselineSlotIndex`），不在第 0 槽時顯示 callout「目前基準＝第 N 槽（…版本名）」；`slots.length > 1` 時每槽都可刪；至少 2 個有效情境才呈現對照
  - 呈現：情境槽列（含健檢摘要小卡）+ 指標對照表（down 指標最大值 warning／最小值 success，全相同不上色）+ 結構差異摘要卡（非基準情境各一張）
  - 後端零改動
- ✅ **規劃指標／健檢 Org Health**（commit `e9da58d`，契約見 [契約-規劃健檢](契約-規劃健檢.md)）
  - `orgHealth.ts` 純函式 + `/health` 頁；指標（管理幅度、層級深度、職能覆蓋、結構風險 findings）
- ✅ **專案職能雙維度（匯報線 × 職能）**（commit `13f5d4a`，契約見 [契約-專案職能雙維度](契約-專案職能雙維度.md)）
