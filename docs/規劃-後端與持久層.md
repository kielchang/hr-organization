# 規劃：後端 API 與持久層（#1）

> 對應「超出本輪範圍」的 #1，是 #2 SSO 與 #3 多租戶的前提。
> 已確認決策：**自建 API + DB**、**Docker 部署**、資料庫**由 Claude 建議**。
> 建立日期：2026-06-06。

## 已確認 / 建議的技術選型

| 範疇 | 採用 | 理由 |
|------|------|------|
| 部署 | **Docker（docker-compose）** | 你的環境用 Docker；雲端中立、本地即可起整套（api + db）|
| 資料庫 | **PostgreSQL**（建議）| 組織資料關聯性高（員工×組別×職級×多主管），需外鍵與查詢；關聯式最契合 |
| 後端語言/框架 | **Node.js + TypeScript + Fastify**（建議）| 與前端同語言、可共用型別與驗證邏輯；Fastify 輕量、效能佳、schema 驗證內建 |
| ORM / 遷移 | **Prisma**（建議）| 型別安全、migration 工具完善、與 Postgres 整合佳 |
| 驗證/序列化 | **zod**（與前端共用 schema 可能性）| 請求驗證、與 TS 型別一致 |

> 以上框架／ORM 為建議；你若偏好（如 NestJS、Drizzle、Express）可在 P1 階段低成本更換。

## 儲存庫結構

維持單一 repo，新增 `server/` 子專案（前端維持在根目錄）：
```
/                # 前端（React/Vite）
/server          # 後端（Fastify + Prisma）
  src/
  prisma/schema.prisma
  package.json   # 後端自有相依與 scripts
  Dockerfile
docker-compose.yml   # db + api（+ 可選 web）
```
- 前端工具鏈（eslint/tsc/vitest）**排除 `server/`**，後端自帶工具鏈，互不干擾。
- 共用型別：以 `src/types/org.ts`、`bpmn.ts` 為單一事實來源，後端參照同形狀（必要時抽 `shared/`）。

## 漸進式導入（低風險、可隨時回退）

採「**先文件化版本、後正規化**」策略，讓前端能以最小改動切換，且保留 localStorage 作離線快取／後備。

- **P1 骨架**：`server/` + docker-compose（Postgres）+ Fastify health endpoint + Prisma 初始化 + 後端測試 + CI/verify 納入後端。前端不動。
- **P2 版本持久化 API**：`org_version`（JSONB data + metadata）與 `org_draft` 表，提供：
  - `GET/POST/DELETE /api/versions`、`GET /api/versions/:id`
  - `GET/PUT /api/draft`
  鏡射現有 `publishedVersions` + draft 模型。
- **P3 前端接線（feature flag）**：新增 API client 抽象層；以 `VITE_API_URL` 有設時走 API、否則回退 localStorage。前端逐頁切換、可灰度。
- **P4 正規化**：將 OrgData 拆成 `employee`/`group`/`job_level`/`assignment`/`change_entry` 關聯表，提供實體級 CRUD 與跨版本查詢；JSONB 版本保留作快照。
- **P5 BPMN 持久化**：`bpmn_process` 等表，鏡射 `BpmnProvider`。
- **P6 認證接點**：預留 auth middleware 介面，銜接 #2 SSO（Entra ID）。

## 認證（本階段）
- P1–P5 先以開發用簡易保護（環境變數 API key 或本地開放），認證正式接 #2。
- 多租戶（#3）所需的 `tenant_id` 欄位於 P4 正規化時預留，先單租戶。

## 驗證與 CI
- 後端自有 `npm run verify`（tsc + lint + test）。
- 根 `npm run verify` 與 pre-push、CI 擴充為「前端 + 後端」皆需綠。
- 後端測試用 Vitest + 測試資料庫（docker 內的 Postgres，或 testcontainers／sqlite 後備視情況）。

## 驗收（P1）
- `docker compose up` 可同時起 Postgres 與 API；`GET /api/health` 回 200。
- `cd server && npm run verify` 全綠。
- 前端 `npm run verify` 不受影響、仍全綠。
