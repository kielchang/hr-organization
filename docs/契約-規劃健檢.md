# 介面契約 — 規劃指標 / 健檢（Org Health Check）

> 協調者（Software Architect）產出的開發契約。各角色照本契約開發，**不得自改契約**（要改回報協調者）。
> 對應方向：以 HR 規劃為定位，讓規劃者能**量化評估**一個組織結構好不好。
> 狀態：草案 → 開工。最後更新：2026-06-06。

## 0. 目標與非目標

**目標**：從 `OrgData` 推導一組**規劃決策指標與健檢訊號**，回答「這個結構好不好、哪裡有風險」：管理幅度、層級深度、職能覆蓋缺口、結構風險（斷鏈／循環／單點風險）。以一個「規劃健檢」頁呈現摘要卡片 + 可行動的警示清單。

**v1 非目標（明確排除）**：門檻的 UI 可調（v1 用合理預設，僅以 options 參數傳入）；主管「總部屬（子樹）」負載（v1 只算直接部屬 span）；headcount 目標與「對目標的空缺率」（資料模型無目標）；指標歷史趨勢；健檢報告匯出；虛線主管的 span（v1 以主匯報線計算）。

## 1. 架構決策（ADR 摘要）

與「專案職能雙維度」同模式：**前端純函式服務 + 新頁面，後端零改動**（指標全部由 `OrgData` 即時推導）。**重用**既有 `functionCoverage`（職能缺口）、`validators` 的匯報循環偵測、`assignmentLevels` 回填的 `Assignment.level`（層級）。不重造輪子、不動資料模型。

## 2. 服務契約（純函式）— 新增 `src/services/orgHealth.ts`

單一進入點 `buildOrgHealth(data, options?)`，回傳型別於檔內 export：

```ts
export interface SpanEntry { supervisor: Employee; directReports: number }
export interface SpanOfControl {
  entries: SpanEntry[];      // 依 directReports 降冪
  average: number;           // 有部屬的主管平均
  max: number; min: number;
  supervisorCount: number;
  wide: SpanEntry[];         // directReports > wideSpanThreshold（預設 8）
  narrow: SpanEntry[];       // directReports === 1（潛在冗餘層級）
}
export interface DepthStat {
  maxDepth: number;
  perLevel: { level: number; count: number }[]; // 各層人數（依主歸屬 level）
}
export interface OrgHealthFinding {
  id: string;
  severity: 'warning' | 'info';
  category: 'span' | 'depth' | 'function' | 'chain' | 'cycle' | 'spof';
  message: string;          // 繁中、可讀、可行動
  employeeId?: string;      // 供 UI 連結
  groupId?: string;
}
export interface OrgHealthSummary {
  activeEmployees: number;
  departments: number;      // kind==='department' 且 active
  functions: number;        // kind==='function' 且 active
  supervisors: number;      // 有 ≥1 直接部屬的人
  avgSpan: number;
  maxDepth: number;
  warningCount: number;     // findings 中 severity==='warning' 數
}
export interface OrgHealth {
  summary: OrgHealthSummary;
  span: SpanOfControl;
  depth: DepthStat;
  functionCoverage: FunctionCoverage;  // 直接取用 buildFunctionCoverage(data)
  findings: OrgHealthFinding[];         // 跨類別的扁平警示清單（供清單呈現）
}
export function buildOrgHealth(
  data: OrgData,
  options?: { wideSpanThreshold?: number }   // 預設 8
): OrgHealth
```

### 指標定義（務必照此語意，避免歧義）
- **主管 / 直接部屬（span）**：以**主匯報線**計。員工 Y 的「直屬主管」＝ Y 的**主歸屬**（`isPrimaryGroup===true`）那筆 assignment 的 `primarySupervisorId`。`directReports(X)` ＝ 主管為 X 的不重複 active 員工數。只計 active 員工與 active 主管。
- **層級深度（depth）**：取每位員工**主歸屬**的 `Assignment.level`（已由 `assignmentLevels` 回填）。`maxDepth`＝最大 level；`perLevel`＝各 level 人數。
- **職能覆蓋**：直接 `buildFunctionCoverage(data)`，把 `functionsWithoutMembers`、`functionsWithoutLead`、`crossFunctionLoad` 帶入 findings 與呈現。
- **結構風險 → findings**：
  - `chain`（斷鏈）：active 員工**無任何 active 歸屬**（孤兒）；或主歸屬的 `primarySupervisorId` 指向**不存在或 inactive** 的員工（懸空主管）。
  - `cycle`（循環）：重用 `validators` 的匯報循環偵測，每條循環一筆 finding。
  - `spof`（單點風險）：**某主管是 ≥2 名部屬的唯一主管**（那些部屬主歸屬的 `supervisorIds` 僅含此人、無備援）→ 該主管不可用會讓多名部屬失去主管。每個此類主管一筆 finding，訊息含影響人數。（單一部屬不報，避免噪音。）
  - `span`：每個 `wide`／`narrow` 主管各一筆 finding（wide=warning、narrow=info）。
  - `depth`：`maxDepth` 超過合理值（預設 > 6）一筆 info finding。

### Findings 嚴重度
- warning：wide span、斷鏈、循環、spof、無 lead 職能、無成員職能。
- info：narrow span、過深層級、跨職能高負載（crossFunctionLoad 前段）。

## 3. UI 契約 — 新增頁面 `src/pages/OrgHealthPage.tsx`，路由 `/health`

- **導覽**：`Layout` 加一個入口「規劃健檢」。
- **資料來源**：與其他頁一致，取當前 orgData（草稿或發布版本），用既有 hook（參考 `OrgChartPage` 取資料的方式）。
- **版面**：
  1. **摘要卡片列**（`OrgHealthSummary`）：active 人數、部門/職能數、主管數、平均 span、最大層級、警示數。
  2. **管理幅度**區：分佈（可簡單以數字/列表）＋ 過寬/過窄主管清單。
  3. **層級深度**區：各層人數。
  4. **職能覆蓋**區：重用既有 `FunctionCoveragePanel`（或精簡版）呈現無成員/無 lead 職能、跨職能負載。
  5. **結構風險 / 警示清單**：以 `findings` 列出，severity 用 Badge（warning/info）標色，可讀訊息；若有 employeeId/groupId 可標示。
- 沿用既有 shadcn 元件（Card、Badge、Table）、`uiSemantics`/`selectOptions` 既有語意色。**不另造設計系統**。

## 4. 後端：不涉及

指標全部由 `OrgData` 前端推導，**不需改 `server/`**、不需 Prisma 變更。後端角色本輪不參與（協調者已確認）。

## 5. 角色分派與邊界

| 角色 | 範圍 | 邊界 |
|---|---|---|
| 協調者（主執行緒） | 本契約、整合驗收 | 僅契約／文件 |
| 前端（Frontend Developer） | §2 服務 + §3 頁面/導覽（`src/`），**不寫測試** | 不碰 `server/`、不改契約 |
| 測試/QA（Test Results Analyzer） | `orgHealth.ts` 純函式測試（各指標/各 finding 類別/邊界）+ 頁面 render smoke；跑完整 `verify` | 僅測試碼，不改實作 |
| 程式碼審查（Code Reviewer，含資安視角） | 唯讀審查 §2–§3 | 只回報不改 |
| 文件（Technical Writer） | 系統設計文件 §4/§6、待辦清單 | 僅文件 |

**驗收門檻**：`npm run verify` 綠（QA 補測試達覆蓋率門檻）+ 各角色把關通過 → 協調者於 `integration` 提交。
