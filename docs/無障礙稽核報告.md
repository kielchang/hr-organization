# 無障礙稽核報告（Accessibility Audit Report）

## 稽核概觀

- **產品／範圍**：HR 組織調整工具（React + TypeScript + Vite）主要頁面、表單／對話框與核心 UI 元件
- **稽核標準**：WCAG 2.2 Level AA
- **稽核日期**：2026-06-06
- **稽核者**：AccessibilityAuditor
- **使用工具**：axe-core（透過 `vitest-axe`，於 jsdom 執行）、`@testing-library/react`
- **重要限制**：jsdom 無法計算版面與顏色，故 **`color-contrast` 規則停用**（見 `src/test/axe.ts`）。色彩對比（WCAG 1.4.3 / 1.4.11）、鍵盤焦點順序、螢幕報讀器實機行為等仍須於真實瀏覽器與輔助科技另行驗證；本報告僅涵蓋自動化可偵測之結構性議題。

## 稽核方法

- **自動化掃描**：對每個視圖／元件以 `renderWithProviders`（OrgProvider + BpmnProvider + MemoryRouter，自動載入 seed 資料）渲染後，針對渲染結果執行 axe-core。
- **對話框處理**：Dialog 內容透過 React Portal 掛載於 `document.body`，render 回傳的 `container` 為空，故改抓 `role="dialog"` 元素本身稽核——即使用者實際操作的表單內容。
- **逐元件隔離**：每個視圖於獨立 `it` 中渲染並在 `afterEach` 清理（避免多次渲染共用 DOM 造成偽陰性）。

## 發現的問題

### 問題 1：Select 下拉控制項（combobox 按鈕）無可及名稱

- **WCAG 準則**：4.1.2 Name, Role, Value（Level A）
- **規則 id**：`button-name`（axe-core）
- **嚴重度**：Critical
- **使用者影響**：`<SelectTrigger>` 在 Base UI 中是 `role="combobox"` 的 `<button>`。雖然 `<SelectValue>` 會顯示目前選取的文字，但該文字並未成為按鈕的「可及名稱（accessible name）」。螢幕報讀器（VoiceOver / NVDA / JAWS）只會讀出「按鈕（button）」或「combobox」，使用者無從得知這是「狀態篩選」「組別」「職級」還是「主主管」。鍵盤／報讀器使用者因此無法有效操作這些下拉。
- **發生位置**：
  - `src/components/EmployeeList.tsx:77`（狀態篩選 Select，連帶使 **PeoplePage** 違規）
  - `src/components/AssignmentEditor.tsx:136`（組別）、`:158`（職級）、`:205`（主主管）
- **現況**：`<Label>` 與 `<SelectTrigger>` 之間缺少關聯——`<Label>` 沒有 `htmlFor`，`<SelectTrigger>` 也沒有 `id`：

  ```tsx
  <Label>組別</Label>
  <Select value={...}>
    <SelectTrigger className="w-full bg-background">
      <SelectValue>{...}</SelectValue>
    </SelectTrigger>
    ...
  </Select>
  ```

- **建議修法**（擇一）：
  1. **Label 關聯（建議）**：為 `<Label htmlFor="...">` 與 `<SelectTrigger id="...">` 加上配對的 id，如同 `EmployeeForm.tsx` / `GroupForm.tsx` 既有作法（該二處 Select 已正確關聯，稽核通過）：

     ```tsx
     <Label htmlFor="assignment-group">組別</Label>
     <Select value={...}>
       <SelectTrigger id="assignment-group" className="w-full bg-background">
         <SelectValue>{...}</SelectValue>
       </SelectTrigger>
     </Select>
     ```

  2. **aria-label**：若無視覺標籤需求，直接在 `<SelectTrigger aria-label="狀態篩選">`。
- **驗證方式**：取消 `src/components/EmployeeList.a11y.test.tsx`、`src/pages/pages.a11y.test.tsx`（PeoplePage）、`src/components/forms.a11y.test.tsx`（AssignmentEditor）對應的 `it.skip` 後重跑 `npx vitest run`，應全數轉綠。實機以 VoiceOver/NVDA 進入下拉，應讀出對應標籤名稱。

### 問題 2：純圖示按鈕無可及名稱（刪除流程）

- **WCAG 準則**：4.1.2 Name, Role, Value（Level A）；亦關聯 1.1.1 Non-text Content（Level A）
- **規則 id**：`button-name`（axe-core）
- **嚴重度**：Critical
- **使用者影響**：BPMN 流程清單每列的「刪除」按鈕僅含一個 `<Trash2>` 圖示、無文字也無 `aria-label`，圖示本身對報讀器不可見。報讀器使用者只會聽到「按鈕」，無法得知這是刪除流程的高風險操作。
- **發生位置**：`src/pages/BpmnListPage.tsx:126-128`
- **現況**：

  ```tsx
  <Button variant="ghost" size="sm" onClick={() => setConfirmId(p.id)}>
    <Trash2 className="size-4 text-destructive" />
  </Button>
  ```

- **建議修法**：為按鈕加上可及名稱（並標示圖示為裝飾性）：

  ```tsx
  <Button
    variant="ghost"
    size="sm"
    aria-label={`刪除流程「${p.name}」`}
    onClick={() => setConfirmId(p.id)}
  >
    <Trash2 aria-hidden="true" className="size-4 text-destructive" />
  </Button>
  ```

  > 參考良好範例：`GroupsPage.tsx:84` 的編輯鈕已有 `aria-label="編輯"`；`AssignmentEditor.tsx:120` 的取消鈕已有 `aria-label="取消"`。建議比照，並讓名稱包含流程名稱以利區辨。
- **驗證方式**：取消 `src/pages/pages.a11y.test.tsx`（BpmnListPage）的 `it.skip` 後重跑應轉綠。

### 問題 3（函式庫層級）：對話框 focus-guard sentinel 無可及名稱

- **WCAG 準則**：4.1.2 Name, Role, Value（Level A）
- **規則 id**：`aria-command-name`（axe-core）
- **嚴重度**：Serious
- **使用者影響**：Base UI 的 Dialog 會在對話框「外側」注入隱形 focus-guard 哨兵元素（`role="button"`、`tabindex="0"`、`data-base-ui-focus-guard`、`data-base-ui-inert`），用於焦點圍欄。axe 會將其標記為「ARIA command 缺少可及名稱」。這些元素標示為 `inert` 且尺寸 1×1、視覺隱藏，實務上不參與互動，但仍出現在無障礙樹中。
- **發生位置**：所有使用 `Dialog` 的元件（`EmployeeForm`、`GroupForm`、`ConfirmDialog`、`ChangeLogPage` 的 diff 對話框）。注意：此違規位於對話框「外側」的 portal 兄弟節點，**不在** `role="dialog"` 內，故掃描 dialog 元素本身時為乾淨——僅在掃描整個 `document.body` 時出現。
- **現況**：屬 Base UI（`@base-ui/react`）內部實作產生，**非本專案元件標記缺陷**。專案自身的對話框內容（標題、欄位、按鈕）皆通過稽核。
- **建議修法**：
  1. 追蹤上游 Base UI 版本，待其修正 focus-guard 的可及名稱／角色（理想上這類哨兵不應暴露為 `role="button"`）後升級。
  2. 短期可評估於測試層級對該規則加例外（僅限此函式庫節點），但 **不應修改 production 程式碼**。
- **驗證方式**：升級 Base UI 後，取消 `src/components/forms.a11y.test.tsx` 中掃描 `document.body` 的 `it.skip` 並重跑。

## 做得好的部分（值得保留的模式）

- **Layout** 採用語意化 `<nav>` / `<main>` / `<aside>` / `<header>` 與 `<h1>` 標題，landmark 結構清楚，導覽連結具文字標籤。
- **EmployeeForm.tsx** 與 **GroupForm.tsx** 的所有表單欄位（Input、Select）皆以 `<Label htmlFor>` ↔ `id` 正確關聯——此即問題 1 的正確範本。
- **GroupsPage.tsx:84** 編輯鈕、**AssignmentEditor.tsx:120** 取消鈕、**Layout.tsx:77** 關閉提示鈕，皆為純圖示按鈕但已附 `aria-label`，示範了正確做法。
- **AssignmentEditor** 的主管多選清單以 `<label htmlFor>` 包裹 `Checkbox`，關聯正確。
- **Tabs**、**Badge**、**Button**、**Input** 等核心 UI 元件預設即可及。
- 表格（Table）標頭使用 `<TableHead>`（`<th>`），ChangeLogPage 空狀態以 `colSpan` 正確跨欄。
