## 0. 目標與非目標

**目標**：HR 在組織圖編輯模式調整組織時，即時看到關鍵規劃指標的 before→after 變化（例：平均管理幅度 6.2→4.8、警示 8→5），不必發布或進情境比較就知道「我這次調整把結構變好還變壞」。降低 PM/UXR 都點出的「要發布才能看 diff」摩擦。

**v1 非目標**：完整 diff（已有情境比較）；逐項 finding 變化（只看高層摘要指標）；非編輯模式的呈現（僅編輯模式內）。

## 2. 服務契約（純函式）— `src/services/orgHealth.ts` 新增

```ts
export interface HealthMetricDelta {
  key: 'avgSpan' | 'maxDepth' | 'warningCount' | 'readiness';
  label: string;          // 繁中：平均管理幅度／最大層級／警示數／規劃就緒度
  before: number;
  after: number;
  delta: number;          // after - before
  /** 對該指標 delta 的好壞：avgSpan/maxDepth/warningCount 越小越好；readiness 越大越好 */
  direction: 'improved' | 'worsened' | 'unchanged';
}
export interface OrgHealthDelta {
  metrics: HealthMetricDelta[];  // 固定 4 項，順序：avgSpan, maxDepth, warningCount, readiness
  hasChanges: boolean;           // 任一 metric.delta !== 0
}
export function compareOrgHealth(base: OrgData, draft: OrgData): OrgHealthDelta;
```

### 語意
- avgSpan：`buildOrgHealth(x).summary.avgSpan`，**before/after 先 round 到小數 1 位**再存與算 delta/direction（修訂：原定義存原浮點值，但顯示為 toFixed(1) 時，原值算的 delta/direction 會與畫面矛盾——如 4.83→4.78 兩者都顯示 4.8 卻標「改善 −0.1」。改為以「顯示精度（1 位）」為比較基準，讓 before/after/delta/direction 四者自洽。整數指標 maxDepth/warningCount/readiness 不受影響。）
- maxDepth：`summary.maxDepth`
- warningCount：`summary.warningCount`
- readiness：`buildReadiness(buildOrgHealth(x)).total`
- direction：
  - avgSpan/maxDepth/warningCount：after < before → improved；after > before → worsened；相等 → unchanged
  - readiness：after > before → improved；after < before → worsened；相等 → unchanged
  - **注意 avgSpan「越小越好」是簡化假設**（過小也不理想，但 v1 以「警示減少」為主訊號，avgSpan 僅供參考；direction 用單調規則即可，不做區間判斷）

## 3. UI 契約 — 編輯模式浮層

**位置**：`src/pages/OrgChartPage.tsx`（或其編輯模式子元件）——在編輯模式工具列（`EditModeToolbar`）附近或畫布角落，顯示一個精簡浮層／條。**僅編輯模式顯示**。
- 資料源：`compareOrgHealth(session.baseData, session.draftData)`。
- 呈現 4 指標，每個：label + `before → after`，並以顏色/箭頭標 direction（improved=success ↓/↑、worsened=destructive、unchanged=muted）。
- `hasChanges === false`（還沒動任何東西）時：可顯示「尚無變更」淡樣式，或整條淡化——UI 自決，但不要消失（讓使用者知道有這個即時回饋區）。
- 標題簡短，如「**本次調整的影響**」。
- 沿用既有 shadcn 元件與 uiSemantics 色；不另造設計系統；注意對比（沿用 -foreground 教訓）。
- a11y：箭頭/顏色不可為唯一資訊載體，需有文字（improved/worsened 用「改善/惡化」字樣或 +/- 數字）。
