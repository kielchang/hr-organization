# 介面契約 — BPMN 影響分析重定位（M2）

> 協調者（Software Architect）產出的開發契約。各角色照本契約開發，**不得自改契約**（要改回報協調者）。
> 對應方向：把現有 `BpmnImpactPage` 從「BPMN 流程設計的子工具」收斂為「**HR 變更影響透鏡**」，讓 HR 直接看得懂。
> 狀態：草案 → 開工。最後更新：2026-06-06。

## 0. 目標與非目標

**目標**：HR 完成組織調整後，能直接從主導覽進入「變更影響」頁，看「**這次調整動到哪些作業／決策流程的核准人或路徑**」。不必先理解 BPMN 是什麼。

**v1 非目標**：
- 重寫影響分析演算法（`processImpact.ts` 已可用，沿用）
- 移除 BPMN 設計／模擬／清單頁（仍保留，僅降為次層入口）
- 改變 `BpmnProvider` 資料模型

## 1. 架構決策（ADR 摘要）

**最小變更收斂**：保留所有現有檔案與邏輯，只動三件事：
1. **導覽**：主導覽「BPMN 流程」→ 改為「**變更影響**」直連 `/bpmn/impact`（路由不變，避免破壞既有連結／書籤）。BPMN 清單／設計／模擬頁仍存在，從影響頁底部進入「次層入口」。
2. **頁面文案**：`BpmnImpactPage` 的標題與引導文案改為 HR 視角（不主動提 BPMN 術語）。
3. **次層入口**：影響頁加「管理流程定義」連結到 `/bpmn`，BPMN 子頁仍可獨立使用。

**不採全面下架 BPMN 主導覽**：影響頁的資料來源就是 `store.processes`（BPMN 流程定義），完全藏起來會讓 HR 不知道「為什麼這頁有資料/沒資料」。次層入口保留可發現性。

## 2. UI 契約

### 2.1 導覽（`src/components/Layout.tsx`）
- `{ to: '/bpmn', label: 'BPMN 流程', icon: Workflow }` 改為：
  ```
  { to: '/bpmn/impact', label: '變更影響', icon: TriangleAlert }
  ```
  （`TriangleAlert` 已 import；若覺得語意較重也可用 `ScanSearch`、`Workflow` 維持）
- 順序維持原位（在「情境比較」之後、「調整紀錄」之前）。
- 路由不變：`/bpmn`（清單）、`/bpmn/impact`、`/bpmn/:processId`、`/bpmn/:processId/simulate` 全部保留。

### 2.2 `BpmnImpactPage.tsx` 文案重定位
- **頁首標題**：「流程影響分析」→「**變更影響分析**」
- **頁首副標**：「比較組織調整前後，各 BPMN 流程的核准人與路徑變化」→「**比較組織調整前後，動到哪些作業／決策流程的核准人與路徑——協助規劃決策**」
- **「返回」按鈕**：原本連 `/bpmn`，但 HR 從主導覽直接進來不需要「返回 BPMN」；改為**移除這顆按鈕**，或改成「進階：管理流程定義」（連 `/bpmn`），擇一最小。建議**移除**（與其他主導覽頁一致沒有「返回」）。
- **Tab 文案**：
  - 「變更影響比對」維持
  - 「即時健檢」→「**流程健檢**」（避免與規劃健檢 `/health` 字面重疊造成混淆）
- **頁尾**：新增一段小區塊或連結「**進階：管理流程定義 →**」連到 `/bpmn`，讓使用者能進入清單頁管理 BPMN 流程。
- **頂部引導 callout**（新增，在 Header 下方、BaselineSelector 上方）：一段 HR 友善的「這頁能回答什麼」引導，例如：
  > 完成組織調整後，這裡會告訴你：哪些作業／決策流程的**核准人**因人事變動而改變、哪些流程因匯報線斷鏈而**無法執行**。沒有流程資料時，可至「進階：管理流程定義」設定。

### 2.3 不變
- BpmnImpactPage 的邏輯（`diffProcessImpact`、`analyzeProcessHealth`、Baseline 兩種來源）、其他 BPMN 子頁、`BpmnProvider`、`processImpact.ts`：**完全不動**。

## 3. 後端與服務：不涉及

純前端文案／導覽重定位，無 service／server 改動。
