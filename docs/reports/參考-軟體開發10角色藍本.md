# 軟體系統開發 — 10 個 Agent 角色詳細分工說明

> 用途：作為在 Claude Code 上配置 subagent 的設計藍本。
> 每個角色的五個欄位（核心職責 / 主要產出 / 工具與權限範圍 / 邊界 / 交接關係）可直接對應到 agent 設定。
> 建議起步：先用 **核心 5 個角色**（架構師、後端、前端、資料層、測試），規模或品質要求提高再加其餘 5 個。

---

## 1. 架構師 / 協調者（Architect / Orchestrator）

整個多 agent 系統的「大腦」與上游。其他角色都依賴它的決策與分派。

- **核心職責**
  - 把需求拆解成可獨立開發的工作單元，分派給對應 agent。
  - 定義模組邊界與**介面契約**（API schema、資料結構、模組間的呼叫約定）。
  - 做技術選型決策（框架、函式庫、架構模式）並記錄理由。
  - 整合各 agent 的產出，確保彼此相容、無重複或衝突。
  - 處理跨模組的問題與決策仲裁。
- **主要產出**
  - 系統架構圖、模組劃分。
  - 介面契約檔（OpenAPI / 型別定義 / 資料 schema）。
  - 工作拆解清單與分派計畫。
  - 架構決策紀錄（ADR）的初稿（可交給文件 agent 潤飾）。
- **工具與權限範圍**
  - 可讀全專案；可寫架構文件、契約檔、設定檔。
  - 通常**不直接寫業務實作程式碼**，避免越權與 context 過載。
- **邊界（不該碰什麼）**
  - 不深入個別模組的實作細節（交給對應開發 agent）。
  - 不親自寫測試或部署腳本。
- **交接關係**
  - 上游 → 提供契約與工作單元給後端、前端、資料層。
  - 下游 ← 接收各 agent 完成回報，負責整合與驗收一致性。

---

## 2. 後端開發（Backend）

負責伺服器端的業務邏輯與服務。

- **核心職責**
  - 實作業務邏輯、服務層、領域模型。
  - 依架構師的契約實作 API endpoint。
  - 串接資料層（呼叫 repository / ORM，不自己設計 schema）。
  - 處理驗證、錯誤處理、交易一致性、邏輯層的效能。
- **主要產出**
  - 後端服務與 API 實作程式碼。
  - 對應的單元測試骨架（細節由測試 agent 補強）。
  - API 的實際行為說明（回傳給文件 agent）。
- **工具與權限範圍**
  - 讀寫限定在 server 端程式碼目錄。
  - 可讀契約檔與資料層介面，但唯讀。
- **邊界（不該碰什麼）**
  - 不改資料庫 schema / migration（提需求給資料層 agent）。
  - 不碰前端程式碼。
  - 不自行變更 API 契約（要改先回報架構師）。
- **交接關係**
  - 上游 ← 架構師的契約、資料層的存取介面。
  - 下游 → 提供 API 給前端串接；提供實作給測試與審查 agent。

---

## 3. 前端開發（Frontend）

負責使用者介面與客戶端邏輯。

- **核心職責**
  - 實作 UI 元件、頁面、版面與互動。
  - 狀態管理、路由、表單處理。
  - 依後端 API 契約串接資料、處理載入 / 錯誤狀態。
  - 基本的可及性（a11y）與響應式處理。
- **主要產出**
  - 前端元件與頁面程式碼、樣式。
  - 前端層的單元 / 元件測試骨架。
- **工具與權限範圍**
  - 讀寫限定在 client 端程式碼目錄。
  - 可讀 API 契約，唯讀。
- **邊界（不該碰什麼）**
  - 不改後端邏輯或 API 契約。
  - 不直接存取資料庫。
- **交接關係**
  - 上游 ← 架構師的 UI 規格、後端的 API 契約。
  - 下游 → 提供畫面給測試（E2E）與審查 agent。

---

## 4. 資料層（Database / Data）

把所有資料相關的決策集中於一處，避免前後端各自亂改。

- **核心職責**
  - 設計與維護資料庫 schema、關聯、索引。
  - 撰寫與管理 migration。
  - 查詢最佳化、ORM 模型、資料完整性約束。
  - 對外提供穩定的資料存取介面（repository 層）。
- **主要產出**
  - Schema 定義、migration 檔。
  - Repository / 資料存取介面。
  - 索引與效能調校建議。
- **工具與權限範圍**
  - 讀寫限定在 schema、migration、資料存取層目錄。
  - 可執行 migration 的驗證（在開發環境）。
- **邊界（不該碰什麼）**
  - 不寫業務邏輯（只提供資料存取，邏輯歸後端）。
  - 不碰前端。
- **交接關係**
  - 上游 ← 架構師的資料模型決策、後端的資料需求。
  - 下游 → 提供存取介面給後端使用。

---

## 5. 測試 / QA（Test）

獨立於實作之外的品質驗證者。

- **核心職責**
  - 設計測試案例與測試策略（單元 / 整合 / E2E）。
  - 撰寫並執行測試，回報覆蓋率與失敗。
  - 驗收功能是否符合契約與需求。
  - 建立可重現的測試資料與情境。
- **主要產出**
  - 測試程式碼、測試計畫、覆蓋率報告。
  - 失敗案例清單（交給除錯 agent 或原開發 agent）。
- **工具與權限範圍**
  - **可寫測試程式碼、可讀全部實作；建議不給修改實作的權限**，以維持測試獨立性。
  - 可執行測試套件。
- **邊界（不該碰什麼）**
  - 不修改業務實作來「讓測試通過」（發現問題要回報）。
- **交接關係**
  - 上游 ← 各開發 agent 的實作、架構師的驗收標準。
  - 下游 → 把失敗回報給開發 / 除錯 agent。

---

## 6. 程式碼審查（Code Reviewer）

把關程式碼品質與一致性的獨立角色。

- **核心職責**
  - 審查 diff，找潛在 bug、邏輯漏洞、邊界情況。
  - 檢查命名、結構、可讀性、重複碼、是否符合專案規範。
  - 確認是否偏離架構師的契約與設計。
- **主要產出**
  - 審查意見與改善建議（逐項、可行動）。
  - 風險標記（必須改 / 建議改 / 可選）。
- **工具與權限範圍**
  - **唯讀程式碼 + 產出評論**，不直接改碼，維持審查與實作分離。
- **邊界（不該碰什麼）**
  - 不自行修改程式碼（提建議給原開發 agent）。
- **交接關係**
  - 上游 ← 各開發 agent 提交的變更。
  - 下游 → 把建議退回給原開發 agent 修正。

---

## 7. DevOps / 基礎設施（DevOps / Infrastructure）

負責建置、部署與執行環境。

- **核心職責**
  - 設定 CI/CD pipeline（建置、測試、部署自動化）。
  - 容器化、環境設定、機密與設定管理（流程面）。
  - 基礎設施即程式碼（IaC）、環境一致性。
  - 監控、日誌、告警的基礎建設。
- **主要產出**
  - CI/CD 設定、Dockerfile / compose、IaC 腳本。
  - 部署文件與環境變數規格。
- **工具與權限範圍**
  - 讀寫限定在 CI/CD、基礎設施、部署相關檔案。
  - 可在開發 / 測試環境執行部署驗證。
- **邊界（不該碰什麼）**
  - 不改業務程式碼。
  - 不在未經確認下對正式環境做不可逆操作（部署、刪除）。
- **交接關係**
  - 上游 ← 各開發 agent 的成品、架構師的環境需求。
  - 下游 → 提供可部署的流程；與資安 agent 協作機密管理。

---

## 8. 資安（Security）

從安全角度檢視整個系統。

- **核心職責**
  - 稽核相依套件漏洞、過時版本。
  - 檢視認證 / 授權邏輯、機密管理、輸入驗證。
  - 找常見弱點（注入、XSS、權限提升、資料外洩風險）。
  - 提出修補建議與優先順序。
- **主要產出**
  - 安全稽核報告、風險清單（依嚴重度排序）。
  - 修補建議。
- **工具與權限範圍**
  - 唯讀全專案 + 產出報告；可跑掃描工具。
- **邊界（不該碰什麼）**
  - 一般只提建議，修補交回對應開發 agent（除非專案另行授權）。
- **交接關係**
  - 上游 ← 全專案程式碼與依賴。
  - 下游 → 把風險與建議交給開發 / DevOps agent。

---

## 9. 除錯（Debugger）

專責追查問題與根因。

- **核心職責**
  - 從錯誤訊息、stack trace、log 反查根因。
  - 重現問題、縮小範圍、定位到具體模組與程式行。
  - 提出修正方案（或最小修補）。
- **主要產出**
  - 根因分析、重現步驟。
  - 修正建議或 patch。
- **工具與權限範圍**
  - 可讀全專案、可讀 log、可在開發環境執行重現。
  - 修改實作前建議先取得確認，或交回原開發 agent。
- **邊界（不該碰什麼）**
  - 不做與當前問題無關的重構。
- **交接關係**
  - 上游 ← 測試 agent 的失敗回報、執行期錯誤。
  - 下游 → 把根因與修正交回對應開發 agent。

---

## 10. 文件（Documentation）

把分散的知識整理成可閱讀、可維護的文件。

- **核心職責**
  - 撰寫與維護 README、安裝 / 使用說明。
  - 整理 API 文件、架構決策紀錄（ADR）。
  - 確保文件與實際程式碼同步。
- **主要產出**
  - README、API 文件、ADR、變更紀錄。
- **工具與權限範圍**
  - 讀全專案；寫限定在文件目錄。
- **邊界（不該碰什麼）**
  - 不改程式碼邏輯。
- **交接關係**
  - 上游 ← 架構師的契約與決策、各開發 agent 的實作行為。
  - 下游 → 對所有人提供文件。

---

## 在 Claude Code 上的配置原則

- **Context 隔離**：每個角色獨立 context，是多 agent 最大的價值——後端 agent 不會被前端細節塞爆。
- **用工具權限強制邊界**：例如測試 / 審查 / 資安 給「唯讀 + 產出」權限，比只靠提示詞約束可靠得多。
- **靠契約交接，不靠口頭傳遞**：先讓架構師產出介面契約，其他 agent 照契約各自開發，能大幅減少來回。
- **不可逆操作要先確認**：正式環境部署、刪除、權限變更等，不在未確認下執行。
- **別一次開太多**：5～6 個是甜蜜點；先核心 5 個跑順再逐步擴充。

| # | 角色 | 核心定位 | 寫程式碼權限 |
|---|------|----------|--------------|
| 1 | 架構師 / 協調者 | 拆解、契約、整合 | 僅文件 / 契約 |
| 2 | 後端開發 | 業務邏輯、API | server 端 |
| 3 | 前端開發 | UI、互動 | client 端 |
| 4 | 資料層 | schema、存取介面 | 資料層 |
| 5 | 測試 / QA | 驗證、覆蓋率 | 僅測試碼 |

| 7 | DevOps | CI/CD、部署 | 基礎設施檔 |
| 8 | 資安 | 漏洞、稽核 | 唯讀 + 報告 |
| 9 | 除錯 | 根因分析 | 讀為主 |
| 10 | 文件 | 文件維護 | 僅文件 |
