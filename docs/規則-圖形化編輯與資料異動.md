# 規則：圖形化編輯 → 資料異動

> 本文件盤點**組織圖上的拖曳／連線手勢**如何轉換為**底層資料異動**——每個手勢觸發哪個純函式、改動哪些欄位、經過哪些驗證／防護、寫入哪種 changeLog。
> 內容以**現況程式碼**為準（盤點屬實），是「在組織圖上動一下，資料到底發生什麼事」的單一參考。
> 上層架構見 [系統設計文件](系統設計文件.md)（§4 組織圖三視角、§6 核心服務）；異動的**檢視**見系統設計文件「異動歷程面板」一節。

---

## 前提：所有編輯只動草稿、發布才落地

**圖上的每一個編輯手勢都只寫進「草稿 session」**——具體是 `useOrgFlowEditing` 持有的編輯 session（`session.draftData`），**不動已發布的資料**。

- 進編輯模式 → 以當前已發布版本為 `session.baseData`、複製出可改的 `session.draftData`。
- 拖曳／連線 → 純函式回傳新的 `OrgData`，經 `onDraftChange` 寫回 `draftData`（草稿）。
- 按「**發布**」→ 草稿才落地成**新版本（不可變快照）**，遞增內容版本號。
- 因此任何手勢都是**安全試算**：可隨時捨棄草稿，或在發布前用「異動歷程面板」逐欄審視。

> 編輯都發生在**工作台 `/workbench`** 的兩個**可編輯視圖**——**匯報組織圖**（`OrgFlowChart`）與**組別組織圖**（`GroupOrgFlowChart`）。兩者**共用同一個 `useOrgFlowEditing` session**，編輯的是同一份 `draftData`，可在 Tabs 間切換而不丟失編輯。工作台第 3 視角「**組別歸屬圖**」為**唯讀** membership 檢視（含種類過濾與職能覆蓋），不進編輯、不在本文件的手勢範圍內。（旅程優先 IA 整併後 `/org-chart` 已重導向 `/workbench`，組織圖中心統一在工作台；三視角全貌見 [系統設計文件](系統設計文件.md) §4。）

## 不變式（所有手勢共通）

無論在哪個視圖、用哪種手勢，下列規則一律成立：

| 不變式 | 說明 |
|--------|------|
| **換主管／換組 → 清掉 `level` 層級覆寫** | 層級回歸由**主匯報深度**（`reportingDepth.computePrimaryDepth`）自動計算——「換了主管／換了組，層級自然跟著走」。`assignment.level` 只是稀疏的手動覆寫（刻意垂直拖曳才設值），改主管／改組時這個覆寫會被清掉。 |
| **循環防護是「整體匯報關係」檢查** | 任何手勢套用**後**，以 `detectReportingCycleFromAssignments` 檢查整份匯報關係；偵測到環則**整筆不套用**（回傳原資料 + `error`），UI 把被拖節點視覺位置回滾。不是只看本地兩點，而是看全域是否成環。 |
| **主歸屬唯一** | 設定某筆歸屬 `isPrimaryGroup = true` 時，同一員工其他歸屬的主歸屬旗標自動清除（一人只有一條 home line）。 |
| **失敗即回滾** | 純函式回傳 `{ data, error }`；`error !== null` 時 `data` 為**原資料未變動**，畫布把被拖節點的視覺位置還原，並以 `role="alert"`／短暫 `Alert` 顯示原因。 |

## 一、匯報組織圖（編輯模式，`OrgFlowChart`）

「誰向誰匯報」的視圖。節點＝人員，連線＝匯報關係（實線＝主匯報、虛線＝其他主管）。手勢分流集中在 `OrgFlowChart` 的 `onNodeDragStop`／`onNodeDrag`／`onConnect`／刪邊。

| 規則 | 手勢 | 觸發函式 | 資料異動 | 驗證／防護 | changeLog |
|------|------|----------|----------|------------|-----------|
| **R1** | 拖某節點**疊到另一節點上**（命中員工節點） | `reassignSupervisor` | `primarySupervisorId` ← 新主管；`supervisorIds` 換掉舊的主主管、**保留虛線（dotted）主管**；**清除該歸屬的 `level` 覆寫** | `validateAssignment`（擋自我指派／inactive／找不到員工或組別）＋**循環防護**；失敗回滾被拖節點位置 | `assignment_update`（含 before/after） |
| **R2** | **垂直拖曳**節點（未命中任何目標） | `upsertAssignment` | 寫入 `level` ← 新層（**稀疏覆寫、不向下 cascade 子樹**）；若拖到的層級與原相同則 **no-op** | 既有 upsert 驗證 | `assignment_update`（更新路徑，含 before/after） |
| **R3** | **拉一條連線**（`onConnect`，來源→目標） | `upsertAssignment` | `supervisorIds` 加入來源；**原本無主管**→設來源為 primary，**原本已有主管**→新的為虛線（dotted） | 既有 upsert 驗證 | `assignment_update`（含 before/after） |
| **R4** | **刪一條連線** | `upsertAssignment` | 從 `supervisorIds` 移除該主管；**若刪到的是 primary**→重設主主管 | 既有 upsert 驗證 | `assignment_update`（含 before/after） |

> **R1 vs R2 的分流**：`onNodeDragStop` 以 React Flow v12 `getIntersectingNodes` 偵測 drop target（過濾自己與 `ghost-*`）。**命中員工節點** → 走 R1 改主管；**未命中** → 走 R2 層級覆寫。拖曳過程（`onNodeDrag`）以 `isDropTarget` hover 高亮可放置目標，drop 採 hover 當下已算的 target（所見即所得）。
>
> **鍵盤替代**：拖拉本身無鍵盤替代，但**連線（`onConnect`）與詳情面板（`OrgDetailPanel` 編 `supervisorIds`）為鍵盤可達的等效路徑**，明訂保留不退化。

## 二、組別組織圖（編輯模式，`GroupOrgFlowChart`）

「以組別為主」的視圖。每人一節點（取其在該組的 assignment），同組靠隱藏 X 欄位網格吸附對齊、以背景分區（`groupZone`）標示。編輯態以 `onNodeDragStop`／`getIntersectingNodes` 對拖曳的 employee 成員節點做**雙手勢分流**。

| 規則 | 手勢 | 觸發函式 | 資料異動 | 驗證／防護 | changeLog |
|------|------|----------|----------|------------|-----------|
| **G1** | 拖某成員**疊到另一名成員上**（命中員工節點） | `reassignSupervisor`（同 R1） | 同 R1：改主管、保留虛線、清 `level` 覆寫 | 同 R1：`validateAssignment` ＋循環防護；失敗回滾 | `assignment_update`（含 before/after） |
| **G2** | 拖某成員**到組別背景分區（`groupZone`）空白處**（命中分區） | `reassignEmployeeGroup` | 該筆歸屬 `groupId` ← 新組；**清除該歸屬的 `level` 覆寫** | 目標組必須存在（否則回「找不到組別」）；**主歸屬（`isPrimaryGroup`）只能落部門組**（拖入職能組被擋）；`validateAssignment`（擋同員工重複歸屬同組／inactive）；**循環防護**；**同組 no-op**；失敗回滾 | `assignment_update`（「改組別」可讀摘要，含 before/after） |

> **G1 vs G2 的分流**：drop target 命中**另一名員工節點** → 走 G1，drop target 取 `target.data.employee.id` 的**裸 employeeId**（非作用域化的 `${groupId}::${employeeId}` 節點 id）；命中**群組分區** → 走 G2，落到該分區所屬組。
>
> **co-leader 節點不可拖**：平行共管（co-lead）為**推導不落地**（`assignmentId === ''`），沒有對應的 assignment 可改，因此編輯態不允許拖曳 co-leader 節點。
>
> **拖曳回饋**：hover 高亮 drop target——分區 drop target 帶 `aria` 標註與內框視覺，讓使用者知道「放開會落到這一組」。

## 純函式索引（資料異動的真正入口）

所有手勢最終都呼叫 `src/services/` 下的純函式，UI 只負責手勢偵測與回滾：

| 函式 | 位置 | 用於 | 回傳 |
|------|------|------|------|
| `reassignSupervisor(data, assignmentId, newSupervisorId, operator)` | `orgOperations.ts` | R1 / G1 改主管 | `{ data, error }`（`error===null` 才成功，失敗時 `data` 為原資料） |
| `reassignEmployeeGroup(data, assignmentId, newGroupId, operator)` | `orgOperations.ts` | G2 改組 | `{ data, error }`（同上；同組為 no-op；主歸屬限部門組） |
| `upsertAssignment(...)` | `orgOperations.ts` | R2 層級覆寫 / R3 連線 / R4 刪邊 | 新 `OrgData` |
| `validateAssignment(...)` | `validators.ts` | 上述全部的前置驗證 | 驗證結果 |
| `detectReportingCycleFromAssignments(...)` | `validators.ts` | 循環防護 | 是否成環 |
| `computePrimaryDepth(...)` / `effectiveLevel(...)` | `reportingDepth.ts` | 清掉 `level` 覆寫後，層級回歸自動計算 | 深度 map／有效層級 |

> 設計哲學：**手勢只描述意圖，資料異動由純函式統一把關**——驗證、循環防護、changeLog 都在純函式內完成，UI 不重複這些規則，也因此這些規則能被單元測試獨立覆蓋。
