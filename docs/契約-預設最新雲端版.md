# 介面契約 — 資料版本預設「草稿優先，否則最新雲端版」（階段 A）

> 協調者產出。使用者需求：「資料版本預設最新雲端版」。
> AskUserQuestion 定案（2026-06-07）：時機＝**有草稿先保留，否則最新雲端**。
> 離線同步（提醒/回線補同步）屬**階段 B**，另立契約、需使用者確認後再做。本契約只做選版預設。
> 狀態：開工。最後更新：2026-06-07。

## 1. 現況（事實）
- `OrgProvider.createInitialState` 用 `loadAllVersions()`（本機 seed+published）＋ `pickDefaultVersionId`（偏好 seed `org-data`）或沿用 `loadActiveVersionId()`。
- 雲端版本（`apiClient.listVersions()` → `apiVersionToInfo`）在 `useEffect` **非同步**載入 `remoteVersions`，併入下拉 `allVersions`，但**不參與預設選版**。
- 後端啟用：`isApiEnabled()`（`VITE_API_URL`）。docker 8088 build 帶 `VITE_API_URL=http://localhost:3001`（啟用）；`npm run dev`(5174) 未設（停用）。
- `ApiVersion = { id, label, data, publishedAt }`。「最新」＝ `publishedAt` 由新到舊第一筆（tiebreak：id）。

## 2. 目標行為
進入 App 時的預設 active 版本，依序判斷：
1. **有未發布草稿 → 保留草稿**（不切走，最高優先）。
   - 「有草稿」定義：`loadDraft()` 存在，且其內容**與所屬 active 版本資料不同**（有未發布變更）。比較用兩邊 `cloneOrgData` 後序列化、**排除易變欄位 `exportedAt`**（必要時連 `changeLog` 一起排除以免誤判，擇穩）。
   - 草稿乾淨（等於某版本、或只是 seed 無編輯）視為「無草稿」，往下走。
2. **否則，後端啟用且雲端有版本 → 預設最新雲端版**（`remoteVersions` 依 `publishedAt` desc 取第一筆）。
3. **否則（離線/未啟用後端/雲端無版本/載入失敗）→ 維持現況**：`pickDefaultVersionId`（本機 seed/last）。**離線提醒與回線補同步屬階段 B，本階段不做**。

## 3. 實作要點（`src/context/OrgProvider.tsx` 為主）
- 因雲端非同步載入，採「初始用本機預設 → 雲端載入後若符合條件再切換」：
  - `createInitialState`：維持現有本機預設邏輯（含草稿保留），**額外記錄**：(a) 是否有未發布草稿 `hadDirtyDraft`；(b) 一個 ref `autoDefaultLockedRef`（初始 false）。
  - 在既有載入雲端的 `useEffect`（`apiClient.listVersions().then(setRemoteVersions)`）成功後，或新增一個依賴 `remoteVersions` 的 `useEffect`：
    - 條件：`!hadDirtyDraft` 且 `!autoDefaultLockedRef.current` 且 `!userHasManuallySelectedRef.current` 且 remoteVersions 非空。
    - 動作：取最新雲端版 `latest`，若 `latest.id !== activeVersionId` 則 `selectDataVersion(latest.id)`；設 `autoDefaultLockedRef.current = true`（只自動切一次，之後不再覆蓋使用者操作）。
  - **使用者手動切版本不可被覆蓋**：`VersionSelector` 觸發 `selectDataVersion` 時設 `userHasManuallySelectedRef.current = true`（或以「自動切換只在首次 remote 載入且 active 仍為初始自動值」判斷，擇簡單可靠者）。注意 `selectDataVersion` 也被程式內部呼叫——自動切換那次不要把自己誤標記為「使用者手動」。
- 「最新雲端版」挑選函式可加在 `dataVersions.ts`（純函式、好測）：`pickLatestRemoteVersionId(remoteVersions: DataVersionInfo[]): string | null`（依 `exportedAt`/publishedAt desc；空回 null）。
- 不改後端、不改下拉外觀；雲端版被選中時 `data` 經既有 `cloneOrgData`（已 migrate）流程。

## 4. 角色分派
| 角色 | 範圍 |
|---|---|
| 協調者 | 本契約、整合驗收 |
| 前端 | §3（OrgProvider 選版、dataVersions pickLatestRemote、VersionSelector 標記手動），不寫測試 |
| 後端 | 零改動；確認 `/api/versions` 回傳含 `publishedAt`（已存在）即可 |
| 測試/QA | `pickLatestRemoteVersionId` 純函式單元；OrgProvider「有髒草稿→保留／無草稿→切最新雲端／無雲端→本機預設／手動選不被覆蓋」行為測（mock apiClient.listVersions）；跑 verify |
| 程式碼審查 | 自動切換時機正確、不覆蓋使用者選擇、不無限迴圈（effect 依賴與 ref lock）、離線/失敗 fallback、無新攻擊面 |
| 文件 | 系統設計文件（選版預設規則）、待辦/契約 |

## 5. 驗收
- `npm run verify` 綠 ＋ `verify:server` 綠。
- 後端啟用且雲端有版本、無髒草稿：進 App 預設選中「雲端 · 最新」那筆。
- 有未發布草稿：進 App 停在草稿（不被切走）。
- 後端停用（dev 5174）：行為與現況一致（seed/last）。
- 手動切到別的版本後重整：沿用手動選擇（不被自動切回雲端）——除非該選擇已不存在。
